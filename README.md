# 脚注核对：投稿前，把你引用的每一句话都验一遍

写论文的人都知道，定稿前有一道绕不开的工序：**核对引文**。

> 你引了《毛泽东选集》第 1 卷第 8 页的一句话，原书真是这么写的吗？引号里是原话还是差了几个字？那条转述，原文是不是真撑得起你的说法？标的是印刷页还是电子页的页码？

这道工序麻烦在：**琐碎**（一篇论文几十上百条脚注）、**易漏**（人工逐条翻原书，翻到后面就疲了）、**难留痕**（核过没核过、结果如何，事后说不清）。

这个技能把盘点、定位、比对、留痕这些繁琐的部分半自动化，**最终的判断权始终在你手里**。

## 它帮你干什么

**1. 盘点：把脚注和正文一一对上。**  
它读你的 PDF/DOCX，提取每条脚注，并尽量定位到正文中它真正支撑的那句话——是直接引用（引号内原话，需逐字核对）还是间接引用（转述，原文语义撑得住即可），逐条标清。

**2. 出书单：告诉你该找哪些书、翻哪几页。**  
按所有脚注归并出母文献清单：作者、书名（含卷册）、出版社、年份、期号/版号、对应哪几条脚注——方便你按图索骥加以搜集并提供给。

**3. 逐字比对：有了原书，交给它核。**  
把原书 PDF 放进来源目录，它先量这本电子书的页码偏移（每本书都得实测），再翻到目标页比对引号内文字，发现差异会标出供你复核；页码对不上的、标称页找不到那句话的，也会写进疑点。页码探测偶尔会失败，那时它会请你帮忙确认页码。

**4. 留痕：每条脚注一个状态，一眼看清。**  
核到哪一步、哪些确认了、哪些还差书、哪些有疑点，全程有记录，可复查、可交代。

| 状态       | 含义                           |
| -------- | ---------------------------- |
| ✅ 已核实    | 在所核来源版本的范围内，引号内文字与页码均对上      |
| ⏳ 待补原文   | 这本书/材料还没提供，给了再核              |
| ⚠️ 待人工复核 | 发现差异或对不上——疑点列清楚了，改不改、怎么改，由你定 |

## 怎么用（三步）

1. **建一个文件夹**放论文。PDF（页面证据）和 DOCX（真实脚注结构）都有最好；只有 DOCX/PDF 也能跑，页面类核验会标"待补"；
2. **说一句"核对脚注"**，它自动走完盘点 → 引文定位 → 母文献整理，产出两份清单（脚注逐条 + 待核书单）；
3. **把能找到的原书 PDF 放进来源目录**，让它逐条比对、回填状态。

全程它只动自己的工作文件，**你的论文原稿只读不碰**。

## 适合谁

准备投稿、想在交稿前把引文过一遍的作者；帮学生终审稿件、需逐条核对引文出处的导师；收到稿件后核查引文规范性的编辑与审稿人。

## 适用范围

本技能按人文社科论文常见的**页脚注**著录方式设计与测试（直接引用加引号并注明出处页、脚注承载文献信息）。理工科常见的引用体制（如正文编号制、著者-出版年制）是否适用，作者尚未验证。**尾注**（置于文末的注释）同样未经测试——引文定位的逻辑或可部分复用，但不能保证整体适用。

## 使用建议

以下为作者个人环境下的实测参考，不代表基准性能：

- **已验证平台**：本技能在 Codex 与 WorkBuddy 中开发并实际使用；其他智能体平台未经系统测试。
- **推荐模型**：部分环节（如无文本层 PDF 的页面核验）依赖读图能力，建议选用具备多模态能力的模型；作者实测 DeepSeek V4 Flash 即可满足需求。
- **参考开销**（约 1.5 万字论文，WorkBuddy + DeepSeek V4 Flash）：完成"提取脚注 → 定位引文 → 整理母文献 → 生成各产物"的完整流程约 5 分钟出头、消耗 11.6 积分；依据一份来源文献核对 12 条脚注的引文耗时约3分钟，消耗 8 积分。（测试发生在高峰计费时段）同一篇文章使用 ChatGPT 5.6 Luna（快速模式、中等思考强度）整体耗时更长，额度消耗未做观测。
