# 工作流与状态

## 阶段

### 0. 最小输入检查

只识别候选稿件和项目位置，不提取文本、不渲染页面、不建清单。DOCX-only在用户决定前停止；PDF-only询问DOCX后继续。

### 1. 证据准备

建立中文工作区：`00_论文原稿`、`01_版式证据`、`02_来源材料`、`03_核对记录`、`04_工作文件`。原件只复制、不覆盖。生成页面证据和结构索引。正式交付物统一由渲染器写入 `03_核对记录`，无其他输出目录。

### 2. 脚注盘点

逐页登记每个真实脚注：稿件页码、脚注序号、脚注全文、标记位置、脚注结构定位。PDF优先页面与坐标，DOCX优先OOXML真实脚注结构；两者均不得用扁平TXT代替。

### 3. 引文边界

以每个标记为锚点向前构造候选，结合视觉位置、句法、引号、语义和前后脚注。候选必须非空、有界、有证据定位。可标为直接引用、间接引用、连续共引、重叠共引或待人工复核。

这一阶段必须由模型逐条完成并写入规范记录，不能先批量截取正文再交给流水线。每条记录至少经过：页面定位 → 原生文本转录 → 引号和句法边界判断 → 与相邻脚注比较 → 残缺/上溯异常自检。直接引文必须核对完整引号对，连续共引要判断是否属于同一语法单元；不确定时保留有界候选并标记人工复核。只有逐条定界完成后，才进入母文献整理和统一输出。

### 4. 母文献整理

模型在盘点阶段为每条记录填写母文献身份字段（作者/编者、题名含卷册/期次、析出、类型、出版信息；作者判定须有责任标记证据，见 sources.md），识别规则见 sources.md——不依赖 `[X]` 标记，正确处理书名号式、“载”字式、外文 `ed.` 式与转引链（转引后为可核对起点、`//` 后为母文献）。不要把完整脚注文本冒充题名。随后固定来源规范化阶段归并去重、区分卷、册、集、辑、期、日期、档案编号和版本，建立每份母文献对应的脚注位置；模型字段空白时才兜底正则提取，无法安全识别时保留“待人工补判”并记录原文，不阻塞其他记录。

### 5. 局部来源核对

只要用户提供了一本或几份来源，并明确要求核对这些来源，就筛选对应记录，完成这些记录的完整核对，然后将其余记录保留为待补材料。

核对标准按引用类型分层、遇阻处理规则与页码定位方法见 sources.md：直接引用逐字核对；间接引用只验证原文是否在语义上支撑转述，不追求逐字一致；页码定位用"正文区抽样探测 offset → 只到标称页码 → 读实际印刷页码一次跳转校正"（无文本层 PDF 由模型看图执行，见 sources.md）；疑似不符时保留记录、报告用户定夺，不在来源中无限搜索替代出处，也不臆测笔误等结论。

### 6. 统一输出与验收

运行 `scripts/audit_pipeline.py` 生成HTML/CSV后，由模型查看三份实际成果——脚注逐条清单、待核文献准备清单和规范记录——做一次交付前语义终检。重点检查引文残缺、无限上溯、连续共引误拆/误合、母文献题名污染、出版信息遗漏及OCR冲突；必要时回看原始证据，只修正规范记录并用同一入口重渲染一次。仍有疑问就标为 `待人工复核`，不得循环修补。任何结构性闸门失败均不得称为正式完成；没有语义异常时不重复运行。

## 状态词

`待盘点`、`待补原文`（材料未提供）、`待来源`（等同待补原文，兼容旧称）、`待视觉复核`、`待人工复核`、`待人工补判`（母文献身份无法自动识别，需模型/用户回看脚注原文补填）、`用户自行核对`、`用户已核对`、`已核实`、`不适用`。状态不能用空白字段代替。渲染时 `待补原文`/`待来源` 均显示 ⏳。

## 续作

继续任务时先读取进度和输入指纹，只从第一个未通过阶段继续。来源材料新增时只重跑受影响的母文献和脚注；稿件指纹改变时，废弃受影响的页面和记录，不复用旧结论。
